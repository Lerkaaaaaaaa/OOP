ОТЧЕТ О ПРОДЕЛАННОЙ РАБОТЕ: Проект "ММО РПГ с нуля"

1.Обоснование выбора паттерна "Фабричный метод":
В задании требуется создать 3 типа юнитов (пехота, лучники, конница) и по 2 вида для каждого типа. 
Паттерн "Фабричный метод" идеально подходит для этой задачи, так как он инкапсулирует логику создания объектов в отдельном классе-создателе (ConcreteUnitFactory). Клиентский код (в main.cpp) не зависит от конкретных классов юнитов (Swordsman, LightArcher и т.д.), он работает только с абстракцией Unit и интерфейсом UnitFactory.
Почему не "Абстрактная фабрика"? 
Абстрактная фабрика нужна, когда требуется создавать целые семейства взаимосвязанных объектов (например, "Армия Эльфов" и "Армия Орков", где нельзя смешивать юнитов разных рас). В нашей задаче такое строгое разделение на семейства не требуется, поэтому использование Абстрактной фабрики было бы избыточным и усложнило бы архитектуру.
Преимущества выбранного подхода:
- Если в будущем потребуется добавить нового юнита (например, "Тяжелая пехота"), достаточно будет добавить новый класс, унаследованный от Unit, и дописать одну строку условия в метод createUnit фабрики. Класс GameField при этом менять не придется.
- Код становится более безопасным: создание объектов через std::unique_ptr гарантирует отсутствие утечек памяти (RAII).

2. Архитектура проекта (Структура классов)
Проект разбит на файлы .h (объявления) и .cpp (реализация). Каждый класс находится в отдельном файле.
- Attributes (Атрибуты): классы Health, Armor, Attack. Инкапсулируют здоровье, броню и атаку, содержат валидацию (например, здоровье не может быть отрицательным).
- Units (Юниты): базовый абстрактный класс Unit. От него наследуются Infantry (Пехота), Archer (Лучники), Cavalry (Конница). От них наследуются конкретные юниты: Swordsman, Spearman, LightArcher, HeavyArcher, Cataphract, HorseArcher.
- GameField (Игровое поле): класс-контейнер, хранящий сетку (std::vector) с юнитами. Реализует добавление, удаление и лимит юнитов.
- Итератор (GameFieldIterator): реализован собственный класс итератора, который позволяет обходить только занятые клетки с помощью цикла range-for.

3. Особенности реализации
- Управление памятью: используются умные указатели (std::unique_ptr), ручные new/delete не используются (RAII).
- Копирование и перемещение: в GameField реализовано глубокое копирование через виртуальный метод clone() (правило пяти). Семантика перемещения реализована по умолчанию (Move semantics).
- Безопасность: добавление юнита проверяет координаты на выход за границы поля, проверяет клетку на занятость, а также контролирует максимальное количество юнитов (maxUnits).

4. Демонстрационные сценарии (Этап 5)
В файле main.cpp реализовано 6 сценариев:
1) Создание поля и фабрики.
2) Создание юнитов через фабрику.
3) Обход поля через собственный итератор.
4) Тест глубокого копирования (удаление юнита в копии не влияет на оригинал).
5) Тест перемещения.
6) Тест обработки ошибок (попытка поставить юнита на занятую клетку).
